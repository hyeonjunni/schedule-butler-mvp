# Schedule Butler MVP

정제되지 않은 카톡, 이메일 원문, 통화 STT 텍스트에서 일정과 TODO를 추론하고, 사용자의 승인을 받은 뒤 가상 캘린더에 등록하는 iPhone UI 스타일 웹 프로젝트입니다.

## 핵심 아이디어

이 앱은 자동 캘린더 등록기가 아니라 승인형 스케줄 비서입니다.

1. 사용자가 원본 텍스트를 붙여넣습니다.
2. AI가 일정, TODO, 체크리스트, 참석자, 가능한 시간/불가능한 시간을 추론합니다.
3. 앱은 결과를 바로 저장하지 않고 메신저 대화처럼 사용자에게 확인합니다.
4. 확정 일정은 승인 후 캘린더에 등록합니다.
5. 미확정 회의 일정은 공통 가능 시간을 계산해 먼저 제안합니다.
6. 일정 전에는 30분 전 알림과 출발 전 체크리스트를 생성합니다.

## 3일 MVP 범위

포함:

- iPhone 스타일 모바일 웹 UI
- 원본 텍스트 붙여넣기 입력
- GPT API 기반 일정/TODO 후보 추출
- 확정 일정, 시간 조율 중인 일정, 정보 부족 일정 분류
- 참석자별 가능/불가능 시간 추론
- 공통 가능 시간 후보 제안
- 승인/수정/취소 플로우
- 승인된 일정, TODO, 체크리스트 DB 저장
- 오늘 일정, 이번 주 일정, TODO 리스트 화면
- 앱 내부 알림 및 브라우저 알림 기반 30분 전 알림

제외:

- 실제 카카오톡/이메일 계정 연동
- 실제 iOS 푸시 알림
- Apple Calendar/Google Calendar 양방향 연동
- 음성파일 STT 변환
- 이미지 OCR 자동 처리
- 복잡한 반복 일정

## 중요한 UX 규칙

정제되지 않은 원문에서 바로 DB에 저장하지 않습니다.

- 확정 일정: "이렇게 등록할까요?"라고 승인받습니다.
- 후보 일정: "이 시간이 어떤가요?"라고 먼저 제안합니다.
- 충돌/정보 부족: "이렇게 다시 물어볼까요?"라고 메시지 초안을 제안합니다.

## 예시

입력:

```text
김시현: 내일 1시부터 4시까지 안돼요. 나머지는 다 가능
조현준: 토요일은 3~4시부터 가능할거같아요
배민: 저는 애매해서 저녁 7시에 가능이요. 주 토요일 저녁 7시는 안돼요. 일요일 하루종일 가능
나: 토 2-4, 6- 일요일은 회의가 있긴한데 시간이 미정이라 여기서 먼저 정하면 될것같습니다
```

AI 판단:

- 상태: 시간 조율 중
- 바로 등록 금지
- 참석자별 제약을 추출
- 공통 후보가 명확하면 제안
- 충돌이 있으면 추가 질문 초안 생성

승인 메시지 예시:

```text
토요일 16시 이후가 후보로 보이지만, 배민님과 조현준님의 토요일 19시 조건이 충돌할 수 있습니다.
일요일 18시 이전은 일부 참석자에게 가능하지만 사용자의 일정이 미정입니다.

"토요일 18시-19시 사이 또는 일요일 18시 이전 중 가능한 시간이 있는지 다시 확인해볼까요?"
```

## 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

환경 변수:

- `OPENAI_API_KEY`: OpenAI API key
- `AI_MODEL`: 기본값 `gpt-4.1-mini`
- `DATABASE_URL`: PostgreSQL 연결 문자열. 없으면 `.data/schedule-butler.json` 로컬 저장소를 사용합니다.
- `DATABASE_SSL`: 원격 DB에서 SSL이 필요하면 `true`

## 현재 구현된 범위

- iPhone 스타일 모바일 웹 UI
- 카톡/이메일/STT/메모 원문 입력
- OpenAI 기반 일정 추출 API
- OpenAI 실패 또는 key 미설정 시 휴리스틱 fallback
- `confirmed_event`, `negotiating_event`, `needs_more_info`, `todo_only` 분류
- 참석자별 가능/불가능 시간 표시
- 승인/수정/취소 플로우
- 승인 후 일정, TODO, 체크리스트, 알림 저장
- PostgreSQL 저장소와 로컬 JSON fallback
- 오늘/이번 주 성격의 일정 리스트, TODO, 알림 화면
