# Schedule Butler MVP SWOT 분석

작성 기준: GitHub `main` 브랜치의 README, MVP 범위, 구현 상태, 프로젝트 드래프트 문서와 유사 서비스 공식 자료를 바탕으로 정리했습니다.

## 1. 프로젝트 개요

### 프로젝트명

Schedule Butler MVP

### 서비스 한 줄 설명

정제되지 않은 카카오톡 대화, 이메일 원문, 통화 STT, 메모에서 일정과 TODO를 추론하고, 사용자 승인 후에만 가상 캘린더에 저장하는 승인형 AI 스케줄 비서입니다.

### 핵심 사용자

- 카카오톡 단체방에서 약속 시간을 조율하는 사용자
- 대학생 팀플, 스터디, 동아리 운영진
- 프리랜서, 소규모 팀 PM, 프로젝트 리더
- 회의 일정과 TODO가 여러 메시지에 흩어져 관리가 어려운 사용자

### 해결하려는 문제

실제 일정은 캘린더에 바로 입력할 수 있을 만큼 정리된 형태로 전달되지 않는 경우가 많습니다. 사람들은 카카오톡, 이메일, 통화 기록, 회의 메모에서 비정형적으로 약속을 잡습니다.

예를 들어 다음과 같은 대화는 사람이 직접 읽고 정리해야 합니다.

```text
김시현: 내일 1시부터 4시까지 안돼요. 나머지는 다 가능
조현준: 토요일은 3~4시부터 가능할 것 같아요
배민: 토요일 저녁 7시는 안돼요. 일요일 하루종일 가능
나: 토 2-4, 6- 일요일은 회의가 있긴한데 시간이 미정이라 여기서 먼저 정하면 될 것 같습니다
```

이 프로젝트는 이런 원문에서 일정 후보, 참석자, 가능한 시간, 불가능한 시간, TODO, 체크리스트를 추론합니다. 다만 AI가 바로 일정을 등록하지 않고, 사용자에게 먼저 확인받는 승인형 구조를 핵심 차별점으로 둡니다.

## 2. GitHub 기반 프로젝트 분석

### 주요 기능

- 카카오톡, 이메일, STT, 메모 원문 입력
- OpenAI 기반 일정/TODO 후보 추출
- OpenAI API key가 없거나 실패할 때 휴리스틱 fallback 사용
- 일정 상태 분류
  - `confirmed_event`
  - `negotiating_event`
  - `needs_more_info`
  - `todo_only`
  - `not_schedule_related`
- 참석자별 가능/불가능 시간 추출
- 여러 사람의 시간 제약을 바탕으로 공통 후보 시간 계산
- 후보 시간 선택 시 등록 폼 자동 반영
- 답장 초안 복사
- 승인 전 편집, 승인, 취소 플로우
- 승인 후 일정, TODO, 체크리스트, 알림 저장
- 오늘/이번 주 가상 캘린더 화면
- TODO/체크리스트 화면
- 알림 목록과 브라우저 알림
- 승인된 일정의 `.ics` 파일 다운로드

### 기술 스택

- Frontend/Backend: Next.js App Router
- UI: React, TypeScript, iPhone 스타일 모바일 웹 UI
- AI: OpenAI Chat Completions API
- Storage: PostgreSQL 우선, 로컬 개발 시 JSON fallback
- DB Driver: `pg`
- 테스트: Vitest
- 아이콘/UI 보조: `lucide-react`

### 구현 상태

1차 MVP의 핵심 흐름은 상당 부분 구현되어 있습니다.

- 원문 입력부터 AI 추출, 승인 대기 draft 생성까지 구현됨
- 확정 일정과 시간 조율 중인 일정을 구분함
- 확정되지 않은 일정은 `Event`로 저장하지 않는 안전장치가 있음
- 시간 조율 대화의 공통 후보 시간을 최대 3개까지 제안함
- 체크리스트 추천, 알림 생성, `.ics` 다운로드가 구현됨
- 앱이 열려 있을 때 due notification을 확인하고 `shown` 상태로 갱신함
- `npm run test`, `npm run typecheck`, `npm run build` 검증 명령이 정리되어 있음

남은 주요 범위는 다음과 같습니다.

- 실제 카카오톡/이메일 계정 연동
- 실제 Google Calendar/Apple Calendar 양방향 연동
- iOS 백그라운드 push notification
- Service Worker 기반 백그라운드 알림
- 원격 PostgreSQL provisioning과 운영 배포
- 오전/오후가 생략된 시간 표현의 신뢰도 표시
- 후보 시간 우선순위 설명의 자연스러운 한국어 개선

### 문서화 수준

문서화 수준은 높은 편입니다.

- `README.md`: 프로젝트 개요, 실행 방법, 구현 범위
- `docs/MVP_SCOPE.md`: 제품 정의, 입력 범위, 일정 상태, 완료 기준
- `docs/IMPLEMENTATION_STATUS.md`: 구현 완료/부분 구현/남은 작업
- `docs/AI_EXTRACTION_CONTRACT.md`: AI 응답 JSON 계약
- `docs/PROJECT_DRAFT_20260605.md`: 제출용 프로젝트 드래프트
- `docs/DEMO_SCRIPT.md`: 시연 스크립트
- `docs/PRESENTATION_PIPELINE.md`: 발표 자료 생성 흐름
- `AGENTS.md`: 에이전트 협업 가이드

### 배포 여부

현재 GitHub 기준으로 로컬 실행과 프로덕션 빌드는 검증되어 있습니다. 다만 운영 서버에 완전히 배포된 상태라기보다는, 교수님 서버 배포 제약과 계획이 문서화된 단계로 보는 것이 적절합니다.

## 3. 유사 서비스 비교

### Calendly

Calendly는 사용자가 자신의 예약 가능 시간을 링크로 공유하고, 상대가 가능한 시간을 직접 선택하는 예약 자동화 서비스입니다. 공식 페이지 기준으로 최대 6개 캘린더를 연결해 실시간 availability 기반 예약을 자동화하는 방향이 강합니다.

Schedule Butler와의 차이점:

- Calendly는 예약 링크 중심입니다.
- Schedule Butler는 이미 발생한 카카오톡/이메일/메모 대화를 해석하는 데 집중합니다.
- Calendly는 상대방이 예약 페이지에 들어와 시간을 선택해야 하지만, Schedule Butler는 기존 대화 내용을 기반으로 후보와 답장 초안을 만듭니다.

### Google Calendar Appointment Scheduling

Google Calendar의 appointment scheduling은 예약 페이지를 만들고 공유하면 상대가 시간을 예약하고, 예약 결과가 Google Calendar에 자동 반영되는 방식입니다. Google Workspace Business Standard 이상에서는 여러 예약 페이지, 자동 이메일 리마인더, 결제, 여러 캘린더 충돌 체크 같은 기능도 제공합니다.

Schedule Butler와의 차이점:

- Google은 캘린더 안의 예약 인프라가 강합니다.
- Schedule Butler는 캘린더에 넣기 전 단계인 비정형 대화 정리와 승인에 집중합니다.
- Google은 예약 페이지 기반이고, Schedule Butler는 원문 분석 기반입니다.

### Reclaim.ai

Reclaim.ai는 AI Calendar, AI Tasks, Smart Meetings, Calendar Sync, Focus Time, Buffer Time 등 AI 기반 시간 최적화 기능을 제공합니다. 연결된 캘린더와 업무 데이터를 바탕으로 자동으로 시간을 방어하고 회의 일정을 조정하는 방향입니다.

Schedule Butler와의 차이점:

- Reclaim.ai는 캘린더 최적화와 생산성 관리에 강합니다.
- Schedule Butler는 한국어 비정형 대화에서 일정 후보를 추론하고 승인받는 문제에 특화할 수 있습니다.
- Reclaim.ai는 이미 연결된 캘린더 중심이고, Schedule Butler는 캘린더에 등록되기 전의 대화/메모 단계에 초점이 있습니다.

### Motion

Motion은 AI Projects, AI Tasks, AI Calendar, AI Meetings, AI Docs 등을 묶은 업무 생산성 플랫폼입니다. 업무, 프로젝트, 회의, 일정 전체를 AI가 재계획하는 방향입니다.

Schedule Butler와의 차이점:

- Motion은 범용 업무 생산성 슈퍼앱에 가깝습니다.
- Schedule Butler는 더 좁게 “대화 원문 → 일정 후보 → 사용자 승인 → 캘린더 저장” 문제를 해결합니다.
- 초기 MVP 관점에서는 좁은 문제에 집중하는 Schedule Butler가 더 빠르게 검증될 수 있습니다.

### Clockwise

Clockwise는 AI 기반 스케줄링과 Focus Time 최적화로 알려진 서비스였습니다. 다만 공식 사이트 기준으로 2026년 3월 27일부터 제품 제공 종료 및 Reclaim으로의 전환을 안내하고 있습니다.

Schedule Butler 관점의 의미:

- AI 일정 관리 시장은 경쟁이 치열하고 통합이 일어나는 중입니다.
- 범용 AI 캘린더 시장에서 정면 경쟁하기보다, 한국어 비정형 대화와 승인형 일정 등록이라는 틈새를 잡는 편이 유리합니다.

## 4. SWOT 분석

### Strength

- AI가 바로 등록하지 않고 사용자 승인 후 저장하는 구조라 오등록 위험을 줄입니다.
- 카카오톡식 비정형 한국어 일정 조율 문제에 초점이 명확합니다.
- `negotiating_event`를 별도 상태로 분류해 확정 일정과 시간 조율 중인 일정을 구분합니다.
- 참석자별 가능/불가능 시간을 추출하고 공통 후보 시간을 계산합니다.
- 일정뿐 아니라 TODO, 체크리스트, 알림까지 하나의 흐름으로 묶습니다.
- OpenAI 실패 시 휴리스틱 fallback이 있어 로컬 시연 안정성이 높습니다.
- JSON schema normalization, 저장소 안전장치, 회귀 테스트가 있어 MVP 안정성이 좋습니다.
- README, MVP 범위, 구현 상태, AI 계약, 시연 스크립트 등 문서화가 잘 되어 있습니다.

### Weakness

- 아직 실제 카카오톡, 이메일, Google Calendar, Apple Calendar 연동이 없습니다.
- 현재 핵심 입력 방식은 원문 붙여넣기라 사용자가 매번 앱을 열어야 합니다.
- 브라우저 알림은 앱이 열려 있을 때 중심으로 동작합니다.
- 개인정보가 포함된 대화 원문을 다루기 때문에 보안과 신뢰 장벽이 큽니다.
- AI 비용, API 장애, 날짜 해석 오류 가능성이 있습니다.
- 독립 앱으로는 기존 캘린더 앱이나 메신저 앱보다 사용 습관 형성이 어렵습니다.
- 오전/오후 생략, 애매한 한국어 시간 표현 처리에는 추가 고도화가 필요합니다.

### Opportunity

- AI 일정 관리 시장은 Calendly, Google Calendar, Reclaim.ai, Motion 등으로 수요가 이미 검증되어 있습니다.
- 한국에서는 카카오톡 단체방 기반 약속 조율, 팀플, 스터디, 동아리 일정 조율이 매우 흔합니다.
- 글로벌 서비스는 영어권 업무 캘린더 중심이 많아 한국어 대화 원문 특화 서비스의 여지가 있습니다.
- `.ics` 다운로드, Google Calendar API, 카카오톡 공유하기, 모바일 PWA 등으로 단계적 확장이 가능합니다.
- 대학생, 프리랜서, 소규모 팀처럼 가볍고 빠른 일정 조율 도구를 원하는 초기 타깃이 존재합니다.
- 향후 STT, OCR, 날씨 API, 위치 기반 출발 체크리스트로 확장할 수 있습니다.

### Threat

- Google, Microsoft, Kakao, Toss, SKT 같은 플랫폼 사업자가 유사 기능을 기본 앱에 내장할 수 있습니다.
- 카카오톡/이메일 연동은 API 정책, 개인정보, 보안 심사 제약이 큽니다.
- 일정 데이터는 민감 정보라 보안 사고 발생 시 신뢰 회복이 어렵습니다.
- Calendly, Reclaim.ai, Motion 같은 성숙 서비스와 범용 기능 경쟁을 하면 불리합니다.
- AI가 잘못된 날짜나 시간을 제안하면 사용자가 서비스 전체를 신뢰하지 않을 수 있습니다.
- 사용자가 직접 캘린더에 입력하는 것보다 충분히 편하다고 느끼지 못하면 재방문율이 낮아질 수 있습니다.

## 5. SWOT 기반 전략

### SO 전략: 강점을 활용해 기회를 잡는 전략

- “한국어 카톡 원문을 읽는 승인형 일정 비서”로 포지셔닝합니다.
- 대학생 팀플, 스터디, 동아리 일정 조율을 초기 대표 사용 사례로 삼습니다.
- 기존 캘린더 앱이 잘하지 못하는 “대화 해석, 후보 시간 계산, 답장 초안 생성”을 전면에 내세웁니다.
- 시연 샘플과 실제 대화 fixture를 지속적으로 모아 한국어 시간 표현 정확도를 높입니다.
- `.ics` 다운로드 기능을 바탕으로 Google Calendar/Apple Calendar 연동 전에도 실사용 가치를 제공합니다.

### WO 전략: 약점을 보완해 기회를 잡는 전략

- 독립 앱의 입력 마찰을 줄이기 위해 모바일 공유하기, 클립보드 붙여넣기, 카카오톡 대화 복사 가이드를 우선 제공합니다.
- 실제 계정 연동 전에는 캘린더 단방향 등록, `.ics` 다운로드, 답장 초안 복사 기능을 강화합니다.
- 개인정보 우려를 줄이기 위해 원문 저장 최소화, 삭제 기능, 민감정보 마스킹, 로컬 처리 옵션을 제공합니다.
- 오전/오후 생략 시간은 신뢰도나 경고를 표시해 사용자가 쉽게 검토하게 합니다.
- 초기에는 모든 기능을 독립 앱 안에 넣기보다 “일정 후보 정리”라는 핵심 기능의 정확도와 UX를 다듬습니다.

### ST 전략: 강점으로 위협에 대응하는 전략

- 대형 플랫폼이 자동 등록 기능을 내더라도, Schedule Butler는 “사용자 승인과 안전장치”를 차별점으로 유지합니다.
- AI 추론 결과의 근거 문장, 위험 요인, 누락 필드를 화면에 표시해 신뢰도를 높입니다.
- 저장 단계에서 확정되지 않은 일정은 `Event`로 만들지 않는 정책을 계속 유지합니다.
- 글로벌 생산성 앱과 정면 경쟁하지 않고, 한국어 메신저 대화 기반 일정 정리라는 좁은 영역을 선점합니다.
- 회귀 테스트와 샘플 fixture를 늘려 AI/휴리스틱 변경에도 품질을 유지합니다.

### WT 전략: 약점과 위협을 줄이는 전략

- 카카오톡/이메일 직접 연동은 초기 상용화 범위에서 제외하고, 붙여넣기와 공유하기 방식으로 리스크를 낮춥니다.
- 원격 배포 전에는 `.env`, API key, DB password를 절대 저장소에 포함하지 않는 정책을 유지합니다.
- 운영 배포 전 개인정보 처리방침, 데이터 삭제 정책, 보관 기간을 먼저 정의합니다.
- 기능 범위를 무리하게 넓히지 말고 팀플/스터디/소규모 회의 조율에 집중합니다.
- 유료화 전에는 정확도, 편의성, 보안 신뢰를 우선 검증합니다.

## 6. 사업화 방향

### 독립 앱으로 갈지

초기에는 독립 웹앱 또는 PWA로 가는 것이 적합합니다.

이유:

- 빠르게 실사용 검증이 가능합니다.
- 카카오톡, 이메일, 캘린더 API 권한 문제를 피할 수 있습니다.
- 현재 구현된 붙여넣기, 승인, 가상 캘린더, `.ics` 다운로드 흐름과 잘 맞습니다.
- 개인정보와 플랫폼 심사 리스크를 낮출 수 있습니다.

다만 장기적으로 독립 앱만으로는 입력 마찰이 크기 때문에, 공유하기 확장이나 캘린더 연동이 필요합니다.

### 카카오톡/토스/에이닷 등과 연동할지

장기적으로는 연동 가치가 큽니다. 특히 카카오톡 연동은 이 서비스의 핵심 사용 맥락과 가장 잘 맞습니다.

권장 단계:

1. 1단계: 독립 웹앱/PWA, 붙여넣기, 답장 초안 복사
2. 2단계: 모바일 공유하기, 클립보드 자동 인식, `.ics` 다운로드 고도화
3. 3단계: Google Calendar/Apple Calendar 단방향 등록
4. 4단계: 카카오톡 공유/챗봇/채널 연동 가능성 검토
5. 5단계: 토스, 에이닷 같은 생활형/AI 비서 플랫폼과 제휴 검토

초기부터 카카오톡 자동 수집을 시도하면 개인정보와 API 정책 문제가 크므로, 먼저 사용자가 직접 제공한 원문을 처리하는 방식이 안전합니다.

### 초기 타깃 사용자는 누구인지

가장 적합한 초기 타깃은 대학생과 소규모 협업 그룹입니다.

우선순위:

1. 대학생 팀플 조장
2. 스터디/동아리 운영진
3. 프리랜서와 클라이언트 미팅을 자주 잡는 사용자
4. 소규모 스타트업/프로젝트 팀 PM
5. 회의가 많지만 별도 캘린더 자동화 도구를 쓰지 않는 개인 사용자

이 타깃은 카카오톡 기반 조율이 많고, 일정 정리 부담이 크며, 너무 무거운 업무 플랫폼을 원하지 않을 가능성이 큽니다.

### 유료화 가능성은 있는지

유료화 가능성은 있습니다. 다만 초기에는 개인 월정액보다 팀/모임 단위의 가벼운 프리미엄이 더 자연스럽습니다.

가능한 유료화 모델:

- 무료: 월 분석 횟수 제한, 로컬 저장, 기본 후보 제안
- 개인 프리미엄: 무제한 분석, 캘린더 자동 등록, 고급 알림, STT/OCR
- 팀 플랜: 팀별 일정함, 참석자별 가능 시간 히스토리, 회의록/TODO 자동 정리
- B2B/교육기관: 팀플/동아리/학과 일정 조율 패키지

단, 유료화 전에 먼저 검증해야 할 항목은 다음입니다.

- 한국어 시간 표현 정확도
- 사용자가 붙여넣기 과정을 불편해하지 않는지
- AI 결과를 신뢰하는지
- 실제 일정 등록까지 이어지는 비율
- 개인정보 처리에 대한 불안이 얼마나 큰지

## 7. 종합 결론

Schedule Butler MVP의 가장 강한 포지션은 범용 AI 캘린더가 아니라, “한국어 비정형 대화에서 일정 후보를 뽑아 안전하게 승인받는 AI 일정 정리 도구”입니다.

Calendly와 Google Calendar는 예약 페이지 기반 스케줄링에 강하고, Reclaim.ai와 Motion은 캘린더/업무 전체 최적화에 강합니다. 반면 Schedule Butler는 카카오톡 단체방, 팀플, 스터디, 소규모 회의처럼 이미 대화 속에서 일정 조율이 일어난 상황을 정리하는 데 강점을 둘 수 있습니다.

따라서 사업화 방향은 다음 순서가 적절합니다.

1. 독립 웹앱/PWA로 한국어 원문 분석 정확도 검증
2. 대학생 팀플/스터디/동아리 타깃으로 실제 사용성 검증
3. 공유하기, `.ics`, 캘린더 단방향 등록으로 입력/등록 마찰 감소
4. 개인정보 보호와 삭제 정책 정비
5. 카카오톡, 캘린더, AI 비서 플랫폼 연동을 단계적으로 검토

핵심 메시지는 다음과 같습니다.

> Schedule Butler는 AI가 일정을 마음대로 등록하는 앱이 아니라, 비정형 대화에서 일정 후보를 찾아 사용자가 안전하게 승인하도록 돕는 스케줄 비서입니다.
