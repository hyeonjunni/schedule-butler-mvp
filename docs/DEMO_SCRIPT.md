# Demo Script

금요일 시연에서 사용할 최소 데모 흐름입니다. 교수님 서버 배포 전에는 로컬에서만 검증합니다.

## 데모 전 준비

```bash
npm install
npm run test
npm run typecheck
npm run build
npm run dev
```

브라우저:

```text
http://localhost:3000
```

## 1. 회의 조율 데모

입력 탭에서 `회의 조율` 샘플을 선택합니다.

보여줄 포인트:

- 정제되지 않은 카톡 대화 원문
- 참석자별 가능/불가능 시간 추출
- `토 2-4, 6-`, `토요일 7시 전까지 안됨`, `일요일 하루종일 가능` 처리
- 공통 시간 후보 최대 3개 생성
- 후보 선택 시 등록 폼 시작/종료 자동 반영
- `답장 복사`로 상대에게 보낼 메시지 초안 복사

멘트:

> 회의 시간이 아직 정해지지 않은 상태라 바로 Event를 만들지 않습니다. 먼저 참석자별 시간 제약을 계산하고, 공통 후보를 제안합니다.

## 2. 확정 일정 데모

입력 탭에서 `확정 일정` 샘플을 선택합니다.

보여줄 포인트:

- `confirmed_event` 분류
- 등록 전 승인 카드
- 제목, 시작/종료, 장소, TODO, 체크리스트 편집
- 승인 후 캘린더/TODO/체크리스트/알림 저장
- 일정 카드의 `.ics` 캘린더 파일 다운로드

멘트:

> 날짜와 시간이 충분한 일정도 바로 저장하지 않고, 사용자가 확인한 뒤에만 캘린더에 들어갑니다.

## 3. TODO/준비물 데모

입력 탭에서 `TODO/준비물` 샘플을 선택합니다.

보여줄 포인트:

- 일정이 아니라 작업 목록이면 `todo_only`로 분류
- 발표자료, 데모 샘플, 충전기, HDMI 같은 체크리스트 추출
- TODO 탭에서 체크 처리

멘트:

> 일정이 아닌 작업 목록은 Event로 만들지 않고 TODO와 체크리스트 중심으로 저장합니다.

## GPT 프롬프트 설명 위치

발표에서 GPT 요청 구조를 설명할 때는 아래 문서를 엽니다.

- `docs/PRESENTATION_PIPELINE.md`

핵심 설명:

- system prompt로 JSON contract를 강제
- user message에는 입력 타입, 기준 날짜, 원문만 전달
- GPT 응답 이후 normalize 단계에서 날짜/type/classification을 다시 검증
- 미확정 일정은 승인 전 Event로 저장하지 않음
